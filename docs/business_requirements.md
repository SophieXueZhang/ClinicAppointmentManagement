# 景区门票管理系统业务需求说明

## 1. 系统概述

本系统用于管理景区门票的销售、退票及相关统计工作，支持多种票价管理、营业员管理、销售统计等功能。

## 2. 功能需求

### 2.1 票价管理
- 支持多种票种：
  - 成人票
  - 老年票
  - 儿童票
  - 团体票
- 每种票价可独立设置价格
- 支持票种的启用/禁用
- 支持票种描述的添加和修改

### 2.2 营业员管理
- 营业员账号的创建与管理
- 营业员状态管理（启用/禁用）
- 营业员操作日志记录
- 安全的密码存储和验证机制

### 2.3 门票销售管理
- 支持多种票种的销售
- 自动计算销售总额
- 记录销售时间、数量等信息
- 销售记录的查询和统计

### 2.4 退票管理
- 支持已售门票的退票处理
- 记录退票原因
- 记录处理退票的营业员信息
- 自动更新销售记录状态

### 2.5 统计功能
1. 日销售统计 (存储过程实现)
   - 统计指定日期的总销售量和金额
   - 按票种类型统计销售情况
   - 显示销售时段分布
   - 通过触发器自动更新daily_sales_stats表

2. 月度统计 (存储过程实现)
   - 统计指定月份的总销售情况
   - 提供日期维度的销售明细
   - 按票种类型统计月度销售
   - 通过触发器自动更新monthly_sales_stats表

3. 票种销售统计 (存储过程实现)
   - 统计各种票价的销售数量和金额
   - 计算各票种销售占比
   - 分析销售趋势
   - 通过触发器自动更新ticket_type_sales_stats表

4. 营业员业绩统计 (存储过程实现)
   - 统计指定营业员的销售业绩
   - 统计退票处理情况
   - 分析营业员工作效率
   - 通过触发器自动更新operator_sales_stats表

所有统计功能通过数据库触发器实现自动更新，确保数据实时性和一致性。每次销售或退票操作都会自动更新相应的统计表。

## 3. 业务规则

### 3.1 票务规则
- 票价必须大于0
- 团体票需要最少30人购买
- 老年票和儿童票需要年龄限制说明
- 所有票种都可以退票
- 系统自动验证团体票购买数量是否达到最小要求

### 3.2 营业管理规则
- 营业员必须登录后才能进行操作
- 所有操作都要记录详细日志
- 禁用状态的营业员不能进行任何操作
- 禁用状态的票种不能销售

### 3.3 统计规则
- 退票的销售额不计入统计
- 统计数据要考虑时区因素
- 提供多维度的统计分析
